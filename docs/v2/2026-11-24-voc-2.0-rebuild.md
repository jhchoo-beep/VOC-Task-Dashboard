## 1. 2.0 기획 중 화면이 지켜야 할 것
- 9.0은 결과 목표로만 두고 판단 기준으로 쓰지 않음. 판단 기준은 불편 지수
- 불편 지수 = 불편 건수 합 ÷ 분석한 리뷰 수 × 100. 점수와 무관, 경중 가중치 없음, 리뷰 하나에 불편 3개면 3건
- 목표: 전 지점 매달 불편 지수 50 미만(고성은 분기). 결과 목표 신규 리뷰 평균 9.0
- 저점 칭찬 지수 = 9점 미만이면서 글에 칭찬만 있는 리뷰 수 ÷ 분석한 리뷰 수 × 100. 보조 지표, 낮을수록 좋음, 액션 없음
- 수행과제 흐름: 불편 지수를 가장 올린 불편부터 FO가 등록 판단 → 3개월 관찰 → 재발 1건이면 다시 열림 → 3개월 재발 0건이면 완료
- 정렬: 건수 많은 순, 같은 건수면 그 불편이 나온 리뷰 평균 점수 낮은 순(11/8)
- 앱은 판단하지 않음: 원인 문구, 조치 판단을 앱이 만들지 않음. 등록 판단은 FO

## 2. 데이터(기존 Supabase 그대로, 표 추가 없음)
| 화면 값 | 표 |
|---|---|
| 분석한 리뷰(분모), 점수, 불편 수, 칭찬 수 | `voc_review_analysis` |
| 불편 별(현상, 카테고리, 고칠 수 있는 주체, 인용) | `voc_stars` polarity='neg' |
| 리뷰 원문, 번역 | `reviews`(id = voc_review_analysis.review_id) |
| OTA 점수 | `ota_scores`, `ota_properties`, `ota_score_dist` 등(1.0 로직 `lib/otaTrend.ts`, `lib/otaDetail.ts` 재사용) |
| 수행과제, 진행 사항 | `tasks`, `task_logs`, `churn_trigger_links`(1.0 API 재사용) |
| Raw 수집 원본 | `raw_reviews` |

- 저점 칭찬 판정 = `score10 < 9 and neg_count = 0 and pos_count > 0 and has_text`(LLM 분석 기준. 11/23 수기 판독 83건과 모집단이 달라 값이 조금 다름)
- 신규 리뷰 평균 = 분석한 리뷰의 score10 평균
