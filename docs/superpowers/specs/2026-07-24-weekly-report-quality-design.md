# 주간 OTA 리포트 — 보고서 품질 개선 설계

작성 2026-07-24. 대상은 2026-07-23 배포(`806c486`)로 올라간 `/weekly-report`이며,
데이터 레이어의 판정 로직(`lib/weeklyReport.ts`, 커밋 `fba3b44`)은 유지한다.
선행 문서 — `.superpowers/sdd/weekly-report-logic.md` · `.superpowers/sdd/weekly-report-ui.md`.

## 문제

현재 화면은 판정 카테고리 순서(미달 → 통과 → 기준선없음 → 월단위 → 리뷰0건 → 과제)로
전 채널을 나열한다. FO Weekly에서 화면을 띄워놓고 설명하기에는 세 가지가 어긋난다.

1. **결론이 스크롤 맨 끝에 있다.** 회의는 위에서 아래로 읽어 내려간다.
2. **논의 대상과 참고 자료가 같은 비중으로 놓여 있다.** 이번 주 논의는 4건인데
   화면의 대부분을 리뷰 0건 14곳·월 단위 3곳·통과 3곳이 차지한다.
3. **결론 한 줄이 원인 나열이다.** `deriveTasks()`가 `memo` 원문 뒤에 bad 키워드를
   전부 이어 붙이고 "원인 확인"을 덧붙인다. 실제 출력:

   > 제주시티 Agoda — (memo 전문) · 사후 CS 전화 응대 · 주차비 유료 정책 ·
   > 투숙객 주차비 사전 고지 부재 **원인 확인**

   세 키워드는 이미 memo 안에 있는 내용이다. 같은 말이 두 번 나온다.

### 실데이터로 확인한 것 (2026-07-20 주차)

파생 `memo`는 이미 「원인 — 처방」 구조의 완성된 문장이다. 재료가 부족한 게 아니라
화면이 좋은 재료를 망치고 있었다.

| 채널 | `memo` |
|---|---|
| 제주시티 Agoda | 투숙객 주차 유료(1박 15,000원) 예약 단계 사전 고지 부재 — 현장 응대·사후 CS 통화까지 이어진 저평점 컴플레인 1건, 고지 문구 및 응대 스크립트 정비 필요 |
| 동대문 Agoda | 샤워 시 물이 차오르는 객실 배수 불량 — 수리 요청 후 3박 내내 미조치, 대상 호실 특정·수리 이력 확인 |
| 동대문 Expedia | (빈 문자열) |

같은 주 bad 키워드에는 원인이 아닌 감상이 섞인다 — `숙박비 부담`(9점대 리뷰),
`재방문 의사 없음`, `위생 상태 보통`, `서비스 수준 보통`. 밴드 구분 없이 전부 들어온다.

수기 `memo`는 형태가 아예 다르다. 신설 Agoda 2026-07-13은 리뷰어별 서술 5줄짜리 문단이다.
지금은 통과라 화면에 안 뜨지만 미달로 뒤집히면 결론 자리에 문단이 통째로 들어간다.

## 결정 (FO Weekly 화면 공유가 소비 맥락)

| 축 | 결정 |
|---|---|
| 소비 맥락 | FO Weekly 회의 중 노션 임베드 화면 공유 |
| 서사 | 논의 카드 한 벌 + 나머지는 접힌 한 줄 |
| 결론 한 줄의 수준 | **원인까지.** 처방·과제를 AI가 지어내지 않는다 |
| 한 줄 생성 방식 | `ota_complaints.headline` 필드 신설, 배치·수기 양쪽에서 산출 |

| 카드 순서 | 지점 고정(신설·동대문·제주시티·고성), 지점 안에서 격차 큰 순 |

> `headline`이 없으므로 실제로는 폴백(2단계)이 걸려 제주시티 Agoda는
> `투숙객 주차 유료(1박 15,000원) 예약 단계 사전 고지 부재`로 뜬다.
> 동대문 Expedia는 `memo`가 비어 있어 3단계 키워드 폴백으로 `욕실 협소`가 된다.

### 판단

- **결론과 근거를 하나로 합친다.** 직전 초안은 상단 결론 박스와 하단 지점 블록에
  같은 4건을 두 번 렌더했다. 데이터가 많게 느껴지는 원인이 중복이었다.
- **접힌 상태의 숫자는 셋뿐이다** — `누적 → 그 주`, `건수`. 격차 수치는 화살표가
  대신하므로 뺀다. `직전 주 대비`·`추정량`·`기준선 대체`는 펼침 안으로 내린다.
- **소표본 칩은 접힌 상태에 남긴다.** 1건 4.4를 붕괴로 읽지 않게 하는 장치이고
  펼치지 않아도 보여야 한다.
- **통과·월단위·리뷰0건·기준선없음은 숨기지 않고 접는다.** "리뷰 0건은 통과가 아니다"는
  원칙은 접힌 줄의 숫자로 남는다. 펼치면 현행 렌더를 그대로 쓴다.
- **지점 고정 순서.** 격차 순으로 정렬하면 매주 자리가 바뀌어 회의에서 자기 지점을
  찾게 된다. 고정이면 눈이 익는다. 미달 0인 지점은 카드가 없으므로 목록에 나타나지 않고,
  접힌 줄의 집계에만 반영된다.
- **타이포는 화면 공유 기준으로 한 단계 올린다** — 채널명·헤드라인 16px, 숫자 22px,
  보조 12px. 현재 11~13px은 프로젝터에서 읽히지 않는다.

## 2. 데이터 — `headline` 필드

| 대상 | 변경 |
|---|---|
| 마이그레이션 | `ota_complaints`에 `headline TEXT` 추가 (`docs/superpowers/migrations/2026-07-24-ota-complaints-headline.sql`) |
| `scripts/derive-ota-detail.ts` | 불만 분석 LLM이 `headline`(원인 한 줄)과 `memo`(상세 서술)를 별개 필드로 산출·저장 |
| `/parse-reviews` 스킬 Part B | 위 산출 규칙 문서화 |
| `app/api/ota/complaints` | `headline` 입출력 지원 |
| `components/OtaScoresClient.tsx` 데이터 입력 모달 | 「한 줄 요약」 칸 신설 — 수기 행도 같은 품질 |
| `lib/weeklyReport.ts` | `WeeklyCause`를 확장 |

`headline` 작성 규칙: **원인만, 한 문장, 40자 내외, 처방·조치 문구 금지.**
`memo`는 지금 형식을 그대로 유지한다(회고·수기 입력에서 계속 쓰인다).

```ts
interface WeeklyCause {
  headline: string | null      // 결론 자리에 그대로 출력
  headlineSource: 'headline' | 'memoHead' | 'keywords'   // 어디서 왔는지
  detail: string | null        // memo 전문 — 펼침 안
  badKeywords: string[]        // 펼침 안 보조
  hasCause: boolean
}
```

### 폴백 — 과거 주를 깨뜨리지 않는다

소급 마이그레이션을 하지 않는다. 저장된 `headline`이 없는 주는 화면이 순서대로 내려간다.

1. `headline`이 있으면 그대로 (`headlineSource='headline'`)
2. 없으면 `memo`의 첫 `—` 앞부분, 60자 초과 시 잘라 `…` (`'memoHead'`)
3. `memo`도 비었으면 bad 키워드 상위 2개를 ` · `로 (`'keywords'`)
4. 셋 다 없으면 `hasCause=false` → 「원인 미기록」

`—`가 없는 `memo`는 전문의 첫 60자를 쓴다. 수기 문단 memo도 이 규칙에 걸려 잘리므로
결론 줄이 무너지지 않는다.

### bad 키워드를 결론에서 빼는 이유

세 가지가 겹쳤다. ① `memo`가 이미 같은 내용을 담아 중복이다 ② 밴드 구분 없이 실려
9점·10점 리뷰의 `숙박비 부담` 같은 항목이 미달 원인처럼 읽힌다 ③ `재방문 의사 없음`·
`위생 상태 보통`은 원인이 아니라 감상이다. 버리지는 않고 펼침 안 보조로 남긴다.

## 3. 리뷰 원문 드릴다운

- **서버가 미리 실어 내린다.** `getWeeklyReportProps()`가 **미달 채널에 한해** 그 주
  리뷰 원문을 함께 반환한다. 미달은 통상 4~5채널 × 1~3건이라 부담이 없고, 클라이언트
  조회를 만들지 않으므로 노션 임베드에서도 그대로 뜬다(임베드는 인증 API를 못 탄다).
- **주 버킷 매칭은 `lib/otaDetail.ts`의 `parseRawDate`를 그대로 쓴다.** 파생 배치가
  `weekly_avg_score`를 만들 때 쓰는 바로 그 파서이므로, 화면에 뜨는 리뷰가 그 평균을
  만든 리뷰와 **같은 집합**임이 보장된다. 별도 파서를 만들면 두 숫자가 어긋난다.
- **번역**: `raw_reviews`에는 번역본이 없다(아고다 89건 중 한국어 25건). 같은 리뷰가
  `reviews` 테이블에 `content_ko`와 함께 있고 `content` 원문이 두 표에 동일하게
  들어 있으므로, `(branch, ota_site, review_month)` 범위에서 `content` 정규화 키
  (공백·개행 제거 후 앞 60자)로 붙인다. 못 찾으면 원문을 쓰고 **「원문(번역 없음)」**을
  표시한다.
- **정렬**은 평점 오름차순(저평점 먼저). 표시는 `평점 · 국가 · 날짜 · 객실타입` + 본문.
- **표시 개수 상한 없음.** 상한을 두면 가장 나쁜 리뷰가 잘릴 수 있다. 실측 최대가
  채널당 5건 수준이라 상한이 필요 없다.

### 알려진 한계 — 화면에 고지한다

- `ota_site`는 한글명(`아고다`)이고 `ota_properties.ota_name`은 영문(`Agoda`)이다.
  **`lib/otaDetail.ts`의 `OTA_SITE_BY_NAME`을 쓴다** — 파생 배치가 버킷을 만들 때 쓰는
  바로 그 맵이므로 화면과 배치가 같은 행 집합을 본다. (`components/OtaScoresClient.tsx`의
  `OTA_SITE_ALIAS`는 `NOL: ['NOL','야놀자']`처럼 표기가 갈리는 채널을 넓게 잡는 별개
  용도라 그대로 둔다. 이쪽을 쓰면 배치가 세지 않은 행이 화면에만 뜬다.)
- 아고다는 `raw_reviews` 커버리지가 31% 수준이라 **"3건 8.0"인데 원문이 1건만 잡히는
  경우가 생긴다.** 조용히 적게 보여주지 않고 「원문 확보 1/3건」으로 명시한다.
- 트립닷컴은 같은 리뷰가 원문·번역본 두 행으로 적재돼 있다(미해결 이슈). 드릴다운에서
  본문이 사실상 같은 두 건이 나란히 뜰 수 있다. 이번 범위에서 해결하지 않는다.

## 4. 손대지 않는 것

`lib/weeklyReport.ts`의 판정 로직 — 기준선 선택 시점(`pickBaseline`), 5점제/10점제,
월 입도 채널 분리, 소표본 비필터, 리뷰 0건 `silent` 분리, `judgeWeek` 경계. 검증된
29개 테스트를 그대로 보존하고 `cause` 확장과 드릴다운 데이터만 얹는다.

`ota_complaints.memo`의 현재 형식도 유지한다. `headline`은 추가이지 대체가 아니다.

## 5. 검증

| 항목 | 방법 |
|---|---|
| 폴백 4단계 | `resolveHeadline()` 단위 테스트 — `headline` 있음/`—` 있는 memo/`—` 없는 memo/수기 문단 memo/키워드만/전무 |
| 드릴다운 매칭 | 2026-07-20 실측 4채널로, 뽑힌 리뷰 건수가 `reviewCount`와 일치하는지(아고다는 커버리지 미달을 명시적으로 기대) |
| 번역 결합 | 동대문 Expedia `房間很乾淨…` → `방은 아주 깨끗했지만 욕실이 좀 작았어요…` |
| 타입·빌드 | `npx tsc --noEmit` · `npm test`(기존 203 + 신규) · `npm run build` |
| **화면 육안 확인** | 로컬 프로덕션 빌드(`next start`) + 실 Supabase 키로 `/embed/weekly-report?key=…`를 브라우저로 연다. 이 경로는 middleware가 토큰만 검증하므로 **Google OAuth를 타지 않는다** |

마지막 항목이 이번 과업의 조건이다. 지난 두 번의 주간 리포트 작업은 "OAuth 뒤라 육안
확인 못 함"으로 끝났고, 그래서 화면이 실제로 어떻게 보이는지 아무도 모르는 채 배포됐다.

## 6. 이번 범위에서 다루지 않는 것

- **반복·추세 맥락**("3주 연속 미달", "지난달에도 같은 원인"). 재헌님이 이번 아쉬움을
  보고서 완성도로 특정했다. 완성도가 정리된 뒤 별건으로 판단한다.
- **`tasks` 테이블 연결**([기등록]/[신규] 대조, 과제 생성 버튼). 위와 같은 이유.
- **트립닷컴 이중 적재** 해소. 근본이 수집 단계다.
- **처방·과제 문구 생성.** "AI는 사실을 압축할 뿐 해야 할 일을 지어내지 않는다"가
  이번 결정이다.
